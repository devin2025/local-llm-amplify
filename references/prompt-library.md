# 提示词模板库

> 可直接复制。改方括号里的东西，其余别动——结构本身是有讲究的。
>
> 所有模板都遵守同一条布局：**约束在头 → 材料在中间 → 重申约束在尾**。

---

## 通用骨架

```
<role>
你是 [角色]。
</role>

<constraints>
- [硬约束 1]
- [硬约束 2]
- [硬约束 3]
</constraints>

<examples>
[示例，2-3 个]
</examples>

<input>
[任务材料]
</input>

<output_format>
[输出格式要求]
</output_format>

<reminder>
再次确认：[把最关键的一条约束原样复述]
现在开始。
</reminder>
```

## 一、写代码

### 生成

```
<role>
你是资深 [语言] 工程师。
</role>

<constraints>
- 只输出完整可运行代码，用 ``` 包裹
- 代码之外不要写任何解释、总结、使用说明
- 必须显式处理：空输入、边界值、异常路径
- 只使用标准库，不引入第三方依赖（除非明确要求）
</constraints>

<input>
[需求描述]

必须处理的边界条件：
- [列举]
</input>

<output_format>
```[语言]
[完整代码]
```
</output_format>

<reminder>
只输出代码，不要解释。必须处理上面列出的每一个边界条件。
</reminder>
```

### 改 bug

```
<role>
你是调试专家。默认这段代码有问题。
</role>

<constraints>
- 先定位根因，再改。不要一上来就重写
- 如果根因不止一个，全部列出
- 不要顺手重构无关部分
</constraints>

<input>
代码：
```
[代码]
```

现象：
[错误描述 / 报错信息 / 期望 vs 实际]
</input>

<output_format>
ROOT_CAUSE: [一句话说清根因]
LINE: [出问题的位置]
FIX:
```[语言]
[最小改动后的代码]
```
EXPLANATION: [不超过 60 字，为什么这样改]
</output_format>

<reminder>
先定位根因再改，不要重写整段。改动要最小。
</reminder>
```

### 代码审查

```
你是严格的代码审查者，默认这段代码有 bug。
逐条检查：正确性、边界条件、异常路径、命名、性能陷阱。

严格按此格式输出：
ISSUES:
- <具体问题描述>（严重度: 高/中/低）
VERDICT: PASS 或 FAIL

代码：
```
[代码]
```
```

**这个模板的价值在于强制输出 `VERDICT`**——可程序化解析，
流水线能据此决定要不要进入修订阶段。

## 二、数学 / 逻辑推理

```
<role>
你是数学与逻辑专家。
</role>

<constraints>
- 每一步都要写出依据，不要跳步
- 每一步算完自己验算一次
- 最后一行必须用 \boxed{答案} 给出最终结果
</constraints>

<input>
[问题]
</input>

<output_format>
[步骤 1] ...
[步骤 2] ...
...
\boxed{答案}
</output_format>

<reminder>
逐步求解，不跳步，最后一行必须用 \boxed{} 给出答案。
</reminder>
```

### 配套：投票采样

```bash
python vote.py --task-file q.txt --n 8 --profile math_logic_vote --extract boxed
```

### 可用时：交给 Python 算

```
先写出求解所需的 Python 代码，不要自己算。
我会执行代码并把结果给你，你再基于结果继续推理。

问题：[问题]
```

## 三、长文写作

```
<role>
你是 [身份]，擅长 [文体]。
</role>

<constraints>
- 每段必须有具体信息：人名、数字、动作、物件
- 禁止排比句堆砌
- 禁止空洞形容词：深深地、无比、令人深思、仿佛整个世界
- 禁止"不仅...而且..."式套话
- 克制使用破折号，全文不超过 2 处
- 禁止"不是A，而是B"式否定排比
</constraints>

<examples>
[2-3 个风格示例，格式要和期望输出一致]
</examples>

<input>
[写作任务]

核心立意：[一句话]
目标读者：[谁]
字数：[N]
</input>

<reminder>
每段必须有具体信息，禁止排比和空洞抒情。只输出正文。
</reminder>
```

### 去 AI 腔

写作类任务单独跑一遍这个，效果明显：

```
检查下面这段文字，逐条找出 AI 生成痕迹：
1. 排比句堆砌
2. 空洞形容词和空泛抒情
3. "不是A，而是B"式否定排比
4. 破折号滥用
5. 三段式结构（任何地方出现三个并列项）
6. 以"-ing"结尾的浅层分析句（中文里表现为"……着"的堆砌）
7. 模糊归因（"研究表明""众所周知"却不给来源）

输出：
ISSUES:
- <原文片段> → <问题>
REWRITE:
[修改后的版本]
```

## 四、故事 / 情绪类视频脚本

```
<role>
你是短片编剧，擅长 [志怪 / 历史 / 叙事] 题材。
</role>

<constraints>
- 格式：每行以 [画面] 或 [旁白] 开头
- [画面] 只写能拍到的具体东西：谁、在什么光线下、做了什么动作、画面里有什么物件
- [旁白] 必须是能念出来顺口的短句。写完后默读一遍，拗口的改掉
- 抽象情绪必须换成具体物象：不要"他很悲伤"，要"他把烟按灭在已经满了的烟灰缸里"
- 禁止空泛抒情：岁月、沧桑、令人唏嘘、时光荏苒
- 情绪靠细节推进，不靠形容词加码
</constraints>

<structure>
1. 开场 3 秒：钩子。反常、悬念、具体数字、或直接把观众扔进一个场景
2. 中段：一个意象反复出现，每次出现含义不同
3. 结尾：留白，不要点题、不要升华、不要总结
</structure>

<input>
题材：[一句话]
时长：[N] 秒
旁白字数上限：[N] 字
声口：[第一人称 / 第三人称 / 年代感 / 语速]
</input>

<reminder>
[画面] 只写可见的东西，[旁白] 必须能念出来顺口。结尾留白，不要升华。
</reminder>
```

### 配套：编审

```
你是短视频平台的资深编审，只关心观众会不会划走。
检查：
1. 前 3 秒有没有钩子，还是平铺直叙
2. 全片有没有一个能被记住的画面
3. 旁白念出来像不像人话（有没有书面语、长从句）
4. 情绪是递进的还是从头平到尾
5. AI 腔检测（排比、空洞抒情、破折号）

输出：
ISSUES:
- <问题>
SCORE: <1-10>
VERDICT: PASS 或 FAIL
```

完整的脚本方法论见 `video-script-playbook.md`。

## 五、翻译

```
<role>
你是 [领域] 的专业译者。
</role>

<constraints>
- 术语准确优先于文采
- 句式必须符合中文习惯，禁止长定语从句直译
- 禁止"被"字句滥用
- 禁止增译：原文没有的信息不要加
- 禁止漏译：逐句对照，译完自查
</constraints>

<input>

</input>

- 术语对照：[术语] → [译法]
- 存疑处：[哪一句，为什么不确定]
</output_format>

<reminder>
禁止增译和漏译。译完逐句对照自查。
</reminder>
```

## 六、总结

```
<constraints>

- 保留具体数字、人名、时间

</output_format>

</reminder>
```

## 七、结构化输出（给 agent 用）

```
只输出一个 JSON 对象，符合下面的 schema。
不要任何前言、解释、markdown 代码块包裹。
第一行就是 {，最后一行就是 }。

schema:
{
  "answer": "string",
  "confidence": "high | medium | low",
  "sources": ["string"],
  "unknown": ["string"]
}

规则：
- confidence：你对这个答案的把握程度，不确定就写 low
- sources：支撑答案的来源编号，没有则为空数组
- unknown：你不确定或资料里没有的部分，列在这里
- 宁可把内容放进 unknown，也不要编造

问题：[问题]
```

**`unknown` 字段是重点。** 给模型一个"我不知道"的结构化出口，
比让它硬编再事后筛错，成本低得多。

## 八、反面示例：什么样的 prompt 是错的

```
❌ 请你帮我写一个好的视频脚本，要求生动有趣有感染力，
   让人看了很感动，最好是那种能爆款的感觉，谢谢！
```

问题：
- 每个形容词都不可执行（"生动""有感染力""爆款"）
- 没有格式约束，模型会自由发挥
- 没有长度、声口、结构要求
- 客套话占了 30% 的 token
- 模型只能靠猜

```
✅ 写一个 60 秒志怪短片脚本。
格式：每行以 [画面] 或 [旁白] 开头。
[画面] 只写能拍到的具体东西。
[旁白] 短句，能念出来顺口，总字数 200 字以内。
开场 3 秒必须出现一个反常画面。
禁止：排比句、空泛抒情、结尾升华。
题材：一个在夜里替人写信的邮差，某天收到一封写给自己的信。
```

差别不在文采，在**可执行性**。模型能执行"每行以 [画面] 开头"，
执行不了"生动有趣"。
