# 采样参数详解

> 默认参数是给聊天调的，不是给任务调的。这是本地模型最大的隐性损失来源。

## 二、逐个参数

### temperature

缩放 logits 分布的陡峭程度。低 → 确定；高 → 随机。

| 值 | 表现 |
|---|---|
| 0.0–0.2 | 几乎确定。适合抽取、分类、裁判 |
| 0.2–0.5 | 稳定。适合代码、翻译、总结 |
| 0.5–0.8 | 平衡。适合对话、一般推理 |
| 0.8–1.0 | 发散。适合创意写作、投票采样 |
| >1.0 | 本地模型上基本没用，输出会崩坏 |

**常见错误**：把 temperature 调到 0 想让模型"更准确"。
温度只影响采样多样性，**不影响记忆真伪**。温度 0 时模型照样
confidently 地重复一个错误记忆，而且你失去了用投票纠错的机会。

### top_p（nucleus sampling）

保留累积概率达到 p 的最小 token 集合。

- 0.7–0.85：保守，输出集中
- 0.9–0.95：标准
- 0.95–1.0：发散

### top_k

只保留概率最高的 k 个 token。

- 10–20：非常集中
- 20–50：标准
- 50+：发散（本地小模型上超过 100 基本没意义）

### min_p ⭐

**本地模型性价比最高的单参数，没有之一。**

保留所有满足 `p >= min_p × p_max` 的 token。它是动态的：
模型很确定时（p_max 高）候选很少，模型不确定时（p_max 低）候选自动变多。

top_p / top_k 是静态阈值，在分布很平时会放进一堆垃圾 token，
在分布很尖时又过度限制。**min_p 自动适应这个变化。**

- 0.00：关闭
- 0.02–0.05：通用推荐，砍掉长尾
- 0.05–0.10：更激进，输出更干瘪更聚焦
- >0.20：过度，输出会变得机械重复

很多本地模型的"胡言乱语"和"幻觉"就藏在长尾 token 里。
开 min_p 0.03 经常能一次性解决。

**前提**：llama.cpp 支持。LM Studio 不支持——这是 LM Studio 上效果打折的
主要原因之一。

### repeat_penalty

惩罚已经出现过的 token，降低其再次出现的概率。

| 值 | 适用 |
|---|---|
| 1.00 | **数学、代码**（必须） |
| 1.05 | 通用、对话 |
| 1.05–1.15 | 长文写作 |
| >1.15 | 危险 |

**这是本地模型翻车的头号原因。** 默认 1.1 在聊天场景没问题，
但在代码和数学上是灾难：

- 代码：模型不敢复用变量名，生成 `user_name_2_variant_b` 这种诡异标识符
- 数学：打断符号和公式的正常重复，`x` 用了第二次就被惩罚

**做数学和代码时第一件事就是把 repeat_penalty 设为 1.0。**

### presence_penalty vs frequency_penalty

两个都是抗重复，机制不同：

| | 机制 | 效果 |
|---|---|---|
| `presence_penalty` | 只要出现过就罚，不管次数 | 逼模型**开新话题** |
| `frequency_penalty` | 按出现次数累加惩罚 | 压制**高频词** |

**长文写作两个都要开，只开一个效果差一半。**
presence 防的是"整段翻来覆去说同一件事"，frequency 防的是"某个词出现二十次"。

推荐区间：
- presence 0.2–0.5
- frequency 0.1–0.3
- **两者之和不要超过 1.0**，否则中文会变得不通顺

代码和数学：两个都是 0。

### dry_penalty（llama.cpp 的 DRY sampler）

比上面两个 penalty 更聪明的抗重复，专门针对"整段复制自己"。

```bash
--dry-multiplier 0.8 --dry-base 1.75 --dry-allowed-length 2 --dry-penalty-last-n 1024
```

| 参数 | 作用 |
|---|---|
| `dry-multiplier` | 惩罚强度，0 = 关闭，0.8 是常用值 |
| `dry-base` | 指数基数，越大惩罚衰减越快 |
| `dry-allowed-length` | 允许多长的重复（设为 2 表示允许 2 个 token 的正常重复） |
| `dry-penalty-last-n` | 回看多少 token |

**写长文和脚本时必开**，配合 presence/frequency penalty 叠加使用。
这是本地小模型写长文本不掉进循环的关键。

### typical_p

另一种采样思路（按信息量而非概率采样）。在 llama.cpp 上通常**不如 min_p**。
两个不要同时开，会互相干扰。

### mirostat

自适应 perplexity 的采样器。理论和实测都比较边缘，
且**与 min_p 冲突**。除非你明确知道要什么，否则别开。

### xtc（llama.cpp）

Exclude Top Choices：以一定概率排除掉最可能的 token，强制探索。
对创意写作有效，会让输出更"意外"。

```
xtc_threshold 0.1, xtc_probability 0.5
```

与 min_p 方向相反（min_p 砍长尾，xtc 砍头部）。
**两者选一个用**，别同时开。

## 三、采样器顺序

llama.cpp 的默认采样链大致是：

```
penalties → top_k → typical_p → top_p → min_p → xtc → temperature → dist
```

顺序会影响最终结果。可用 `--sampling-seq` 调整：

```bash
--sampling-seq "top_k;min_p;temp"
```

**一般不需要改默认顺序。** 但在调试参数问题时值得知道：
比如 penalty 在最前，意味着它会先改变分布，后续的 top_p/min_p 再在
改变后的分布上工作。

## 四、Qwen 系列特性

### Qwen3（非思考模式）

官方推荐：`temperature 0.7, top_p 0.8, top_k 20, min_p 0`

### Qwen3（思考模式）

官方推荐：`temperature 0.6, top_p 0.95, top_k 20, min_p 0`

**注意 min_p 为 0**——思考模式下不要用 min_p 砍长尾，
会打断长思维链的探索。这也是 `thinking_model` 档位 min_p 设 0 的原因。

### Qwen3 的抗重复

官方建议用 `presence_penalty` 0–2 缓解重复（尤其是思考模式下的长输出）。
注意这个区间比常规建议大得多。长输出时可以从 0.5 往上试。

### Qwen2.5-Coder

代码生成：`temperature 0.2–0.4, top_p 0.8–0.9`
对 `repeat_penalty` 敏感，务必 1.0–1.05。

### 通用

Qwen 系列对参数调优的响应**明显**（比 Llama 明显）。
意味着调参在 Qwen 上的收益更大，值得花时间用 `bench.py` 测。

## 五、常见翻车组合

| 组合 | 后果 | 修法 |
|---|---|---|
| `repeat_penalty 1.1` + 数学 | 正确率显著下降 | 设 1.0 |
| `temperature 0` + 投票 | 所有候选一样，投票失效 | 投票用 0.7–0.9 |
| `min_p > 0.2` | 输出干瘪、机械重复 | 0.02–0.05 |
| `presence + frequency > 1.0` | 中文不通顺 | 各降到 0.3 以内 |
| 推理模型 + CoT 模板 | 双重思考、输出爆炸、死循环 | 不要套模板 |
| `min_p` + `typical_p` 同开 | 互相干扰 | 只用 min_p |
| `min_p` + `xtc` 同开 | 方向相反，效果抵消 | 二选一 |
| 长文不开 DRY | 写到后面开始复制自己 | 开 DRY + 两个 penalty |
| 创意任务用投票 | 选出最平庸的方案 | 多采样人工挑 |

## 六、调优流程

不要同时调所有参数。按这个顺序，一次只动一个维度：

```
1. 先定 temperature（影响最大）
   └─ 从速查表的值开始，±0.2 扫三个点

2. 再定 min_p（0 / 0.02 / 0.05 三档测）

3. 抗重复（仅长文）：presence → frequency → DRY

4. 最后微调 top_p / top_k（影响通常小于前两项）
```

每步用 `bench.py` 量化：

```bash
python bench.py --taskset tasksets/math_basic.json --profile math_logic \
    --sweep temperature=0.2,0.3,0.4 --repeats 3

python bench.py --taskset tasksets/math_basic.json --profile math_logic \
    --sweep min_p=0.0,0.02,0.05 --repeats 3
```

### 测多少才算数

- 题集至少 8 题，含陷阱题（全送分题测不出差异）
- 每题至少 3 次重复（单次结果的随机性会淹没参数差异）
- 用 `llm_judge` 的题集，分数只能横比不能纵比（裁判会偏袒同族模型）

### 什么时候别调参

参数调优的收益通常在 5–20%。**如果你的任务连 few-shot 都没给，
先去做 few-shot**——那一项的收益（10–30%）通常更大，而且几乎零成本。

顺序：few-shot > 参数 > 投票/流水线。别跳步。
